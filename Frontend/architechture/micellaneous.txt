vite.config.js is the configuration file of Vite.
It is used to customize the Vite development server and build process, such as adding plugins, configuring aliases,
proxy settings, environment variables, and other project-specific settings.

vercel.json is the configuration file for Vercel. In my React application, I use it to rewrite all incoming 
routes to index.html. This allows React Router to handle client-side routing and prevents 404 errors when 
users refresh or directly access routes like /dashboard or /profile after deployment.Without vercel.json:
Vercel looks for a physical file or folder named /dashboard.

package.json is the configuration file for a react.js project. It stores project metadata, manages dependencies 
and development dependencies, defines scripts like npm run dev and npm run build, and contains configuration for 
tools such as ESLint and browser compatibility. It helps npm install the required packages and provides a standard 
way to run project commands.

package-lock.json is an automatically generated file created by npm. It stores the exact versions of all installed
dependencies and their sub-dependencies, along with integrity hashes. This ensures that every developer and deployment
environment installs the same dependency versions, making the application stable and reproducible.

| `package.json`                                | `package-lock.json`                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------ |
| Lists the project's dependencies and scripts. | Records the **exact versions** of every installed package and its sub-dependencies.  |
| Created/edited by the developer.              | Automatically generated by npm.                                                      |
| Can contain version ranges like `^1.13.2`.    | Contains exact versions like `1.13.2` along with resolved URLs and integrity hashes. |
| Used to describe the project.                 | Used to ensure everyone installs the exact same dependency tree.                     |

index.html is the entry HTML file of my Vite React application. It contains a root <div> where the React application is 
mounted. The <script type='module'> loads index.jsx, which renders the main App component into the root element. 
It also includes basic HTML metadata like the page title, character encoding, and viewport settings for responsive design.

The public folder stores static assets like images, icons, PDFs, and fonts that are served directly without being 
processed by Vite.

node_modules folder contains all the third-party packages and libraries installed by npm, such as React, Axios,
and Vite. It is automatically generated when we run npm install and is usually excluded from Git because it can 
be recreated from package.json and package-lock.json.

| Feature            | Session-Based Authentication                                   | JWT (JSON Web Token) Authentication                                              |
| ------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **Storage**        | Session data stored on the server                              | Token stored on the client (localStorage, sessionStorage, or HttpOnly cookie)    |
| **Server State**   | Stateful                                                       | Stateless                                                                        |
| **Authentication** | Server checks session ID                                       | Server verifies the JWT signature                                                |
| **Scalability**    | Harder to scale because sessions must be shared across servers | Easier to scale since no session storage is needed                               |
| **Performance**    | Extra database/memory lookup for every request                 | Only token verification is required                                              |
| **Logout**         | Easy—destroy the session on the server                         | Harder—token remains valid until it expires (unless blacklisting is implemented) |
| **Security**       | Session ID is usually stored in a secure cookie                | Depends on where JWT is stored; HttpOnly cookies are safer than localStorage     |
| **Best For**       | Traditional web applications                                   | REST APIs, SPAs, mobile apps, microservices                                      |


The build folder in Vite is called dist. It is created when we run npm run build. 
It contains the optimized production-ready version of the application, including bundled and minified JavaScript, 
CSS, HTML, and other assets. This is the folder that is deployed to production servers like Vercel or Netlify.

index.jsx is the entry point of my React application. It creates the React root and renders the main App component
into the root element in index.html. Before rendering, I wrap the application with React.StrictMode for development 
checks, AppTheme and CssBaseline for consistent Material UI styling, and Auth0Provider to enable authentication across 
the application. I also load global CSS and read Auth0 credentials from Vite environment variables using import.meta.env

App.jsx is the root component of my React application. It sets up client-side routing using React Router and defines
all the application routes. It wraps the app with AuthProvider and HomeProvider to provide global state using the 
Context API. I use a custom ProtectedRoute component to secure pages like Home, History, and authenticated video meetings,
ensuring only logged-in users can access them. It also defines public routes for authentication, password reset,
Auth0 callback, the landing page, and guest meeting access
