WebRTC in Real-Time Communication

WebRTC (Web Real-Time Communication) enables audio, video, and data sharing directly between browsers/devices without plugins. It’s widely used in video calls, conferencing apps, and collaborative tools.

1.  Peer-to-Peer (P2P)
How it works: Each client connects directly to every other client.

Use case: One-to-one calls (e.g., WhatsApp video call, Google Duo).

Advantages:

Simple architecture.

Low latency (direct connection).

No heavy server load.

Disadvantages:

Not scalable beyond 2–3 participants.

Bandwidth usage grows exponentially with more peers (each peer must send multiple streams).

2. Multipoint Control Unit (MCU)
How it works: A central server receives all streams, mixes them into one composite stream, and sends it back to each participant.

Use case: Traditional video conferencing systems (Zoom, Cisco Webex).

Advantages:

Clients only handle one incoming stream (less CPU/bandwidth load).

Simplifies client logic.

Disadvantages:

High server cost (mixing/transcoding is resource-intensive).

Latency can increase due to processing.

Less flexible (everyone gets the same mixed view).

3. Selective Forwarding Unit (SFU)
How it works: A central server receives streams and forwards them selectively to participants without mixing.

Use case: Modern scalable video conferencing (Google Meet, Jitsi, Microsoft Teams).

Advantages:

Efficient: server forwards streams without heavy processing.

Scalable: supports many participants.

Flexible layouts (each client can decide how to display streams).

Disadvantages:

Clients must handle multiple streams (higher CPU/network load).

More complex client logic compared to MCU.

Key Takeaway

P2P → great for direct calls.
MCU → good for small meetings where client devices are weak.
SFU → modern choice for scalable, flexible video conferencing.
